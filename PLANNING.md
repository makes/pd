# pd — implementation plan

## Context

`pd` is a Python TUI application (see DESIGN.md) for cataloguing video snippets: browsing/creating
clips against a live mpv instance, tagging scenes with actors/actresses/links, and generating a
static HTML site + reports from the resulting SQLite database. The repo currently has only
scaffolding: `scene_id.py` (4-char scene ID generator with an offensive-word blocklist) and
`hash.py` (partial-content file hashing). Everything else — schema, CLI, mpv integration, TUI,
sync/site/report — needs to be built from scratch.

Clarified decisions:
- **TUI**: Textual.
- **CLI**: Typer, with subcommands `init`, `ui`, `sync`, `site`, `report`. `pd ui` launches the TUI
  (not the bare `pd` invocation).
- **mpv**: `pd` spawns and owns a single mpv process per session (`--idle`, `--input-ipc-server=<socket>`).
  The user opens source files into that instance themselves (Create tab workflow). For *known* clips
  (List tab / Scene view `p`), `pd` actively issues `loadfile <path> replace start=<seconds>` over the
  IPC socket and does not require manual opening.
- **IPC**: raw Unix domain socket + `json`, no `python-mpv` dependency.
- **DB**: raw stdlib `sqlite3`, no ORM.
- **category**: freeform text, no fixed enum, default `'C'`.
- **Screenshots**: generated by shelling out to `ffmpeg` directly (`-ss <ts> -i <input> -frames:v 1`),
  separate from the `vidclip` tool used for video trims.
- **Report**: printed to stdout *and* written as a timestamped file under `report/`.

## Tech stack & dependencies

Add to `pyproject.toml`:
- `textual` — TUI framework
- `typer` — CLI framework
- `pillow` — thumbnail resizing for `pd site`
- dev: `pytest` (unit tests for non-TUI logic)

External binaries invoked via `subprocess`, assumed present on `PATH` (fail with a clear error if
missing, no bundling): `mpv`, `ffmpeg`, `vidclip`.

Timestamps (`start_ts`, `end_ts`, `screenshot_ts`) are stored as **seconds with fractional part, as
text** (e.g. `"793.986"`), read directly from mpv's `time-pos` property. This format feeds `ffmpeg -ss`,
`vidclip --start/--end`, and mpv `seek`/`loadfile ... start=` uniformly without conversion, and the UI
formats it to `MM:SS.mmm` only for display.

## Data layer (`db.py`)

- One `init_db(project_dir)` that creates `pd.sqlite` with the exact schema from DESIGN.md
  (`clip`, `scene`, `actor`, `actress`, `scene_actor`, `scene_actress`), used by `pd init`.
- Thin query functions per table (`get_scene`, `list_scenes`, `insert_clip`, `set_clip_active`,
  `update_scene_fields`, `add_scene_actor`, `reorder_links`, etc.) — no ORM/model classes, just
  functions returning `sqlite3.Row` (set `row_factory = sqlite3.Row`).
- `links` is stored as a single `text` column (per schema) — encode/decode as a JSON array of URLs
  internally so the "reorder links" feature (ctrl+up/down) is a simple list splice + rewrite.
- All writes commit immediately (autosave requirement — no explicit save step anywhere in the TUI).

## ID generation

- Fix `scene_id.py`'s `in_blocklist`: it currently opens `"reserved_scene_ids.txt"` relative to CWD,
  so it silently no-ops (returns `False`, swallowing `FileNotFoundError`) unless `pd` happens to be
  run from the package directory. Resolve the path via `Path(__file__).parent / "reserved_scene_ids.txt"`.
- Add DB-uniqueness regeneration on top of the existing blocklist check: both `scene_id.generate()`
  and the new `ids.generate_clip_id()` must take a `db` connection/callable and loop
  "generate → check not already in table → return" (blocklist check stays scene_id-only).
- `ids.py`: 7-char lowercase-hex generator (`secrets.token_hex`-based), collision-checked against
  `clip.clip_id`, mirroring the "similar to git short hash" example (`af5c68d`).

## mpv IPC controller (`mpv.py`)

- Cross-platform by design (confirmed needed: dev machine is WSL2, target also includes native
  Windows). `IpcConnection` is transport-agnostic — it only needs an object exposing
  `sendall(bytes)` / `recv(n) -> bytes` / `close()`:
  - POSIX: a real `socket.socket(AF_UNIX)` connected to the path mpv was given via
    `--input-ipc-server=<tmp dir>/mpv.sock` (already satisfies the interface directly, no wrapper).
  - Windows: `WindowsNamedPipeTransport`, backed by `pywin32` (`win32file`/`win32pipe`), connected to
    `\\.\pipe\pd-mpv-<uuid>`. `pywin32` is an environment-marker dependency (`sys_platform == 'win32'`)
    so it's not installed/required on Linux/macOS.
  - `Controller.ensure_running()` branches on `sys.platform == "win32"` to pick the endpoint style,
    spawns `mpv --idle=yes --input-ipc-server=<endpoint> --force-window=yes`, and connects (waiting
    for the socket file to appear on POSIX; retrying `CreateFile` on Windows since named pipes have
    no filesystem existence check).
- Wire protocol: newline-delimited JSON; `send_command(command: list) -> data` request/response call,
  plus `get_property(name)` / `loadfile(path, start=None)` / `seek(seconds)` convenience methods.
  **`loadfile`'s real signature (mpv ≥0.38.0) is `<url> [<flags> [<index> [<options>]]]`** — an
  `<index>` slot was inserted before `<options>`, so setting the start offset requires
  `["loadfile", path, "replace", -1, "start=<seconds>"]` (index `-1` is ignored for the `replace`
  flag but the slot must be present to reach `<options>`). Verified against real mpv 0.40 — omitting
  the index causes mpv to reject `start=...` as an invalid index value. This lets the "open known
  clip at start_ts" flow load-and-seek in one command with no event-wait/polling needed.
- Create tab polls `path` and `time-pos` properties on a Textual timer to drive the live display and
  detect file/mpv-closed changes (timestamps reset per DESIGN.md).
- Single controller instance owned by the Textual `App`, shared by Create tab (manual file open) and
  List/Scene tab `p` (loadfile). The `App`'s shutdown hook is the one required caller of
  `Controller.close()` — it must run regardless of which screen/command last touched the connection,
  since the process is not tied to any single command's success/failure.

## TUI (Textual)

- `App` with 2 tabs (List, Create) using Textual's `TabbedContent`/`Tabs`; Scene view is a
  full-screen `ModalScreen` pushed on top, not a third tab item, per "Enter opens scene in the scene
  view" / "Esc closes the modal and returns to the active tab."
- List tab: two `ListView`/`DataTable`-style panes (scenes left, clips of highlighted scene right),
  `h`/`l`/tab to switch focus, `j`/`k`/arrows/PgUp/PgDn/ctrl+u/d/f/b for scrolling (Textual bindings +
  manual `scroll_page_up` etc. where not built in).
- Create tab: reactive display of mpv `path`/`time-pos`, `i`/`o`/`s` bindings set the three ts
  reactive fields; once all three set, validate (`start<end`, `start<=screenshot<=end`) and call
  `capture.create_scene_and_clip(...)`, then push the Scene modal for the new scene. Reset ts fields
  on scene creation, file change, or mpv close.
- Scene view: 4-pane `Grid` layout (main fields left, actor/actress stacked lists top/bottom-right,
  links list bottom), `+`/`d` on list panes, per-field edit modals on the main pane, ctrl+j/k reorder
  on links. Every field commit writes through `db.py` immediately (no batch save).
- Modals implemented as small `ModalScreen` subclasses returning a value via `dismiss()`.
- **Never name a widget method `_render`** — it silently shadows `Widget._render()`, Textual's own
  internal compositor hook (distinct from the public `render()` you're meant to override). Textual's
  render loop then calls *your* method as if it were its own hook: with the wrong arity, or expecting
  a `Visual` return value your method doesn't produce (`None`), corrupting the widget's render cache
  (`AttributeError: 'NoneType' object has no attribute 'render_strips'`) with no error at the call
  site — it only surfaces later, non-deterministically, deep in the compositor. `CreateView` hit this;
  its refresh helper is named `_refresh_display`. Same applies to other Widget-private names.

## Commands (`cli.py`, Typer app with 5 subcommands)

- `pd init` — refuse if `pd.sqlite` already present in CWD; otherwise create the full directory tree
  from DESIGN.md's layout plus `pd.sqlite` via `db.init_db`.
- `pd ui` — refuse unless `pd.sqlite` exists in CWD; launch the Textual `App`.
- `pd sync` — `sync.py`: for each scene, compute "current clip" (latest `created` where
  `active=true`), ensure its video/screenshot exist (restore from `trash/` by filename match, else
  regenerate: `ffmpeg` for screenshot, `vidclip trim` for video, `--copy` omitted when source
  extension isn't mp4-container-safe — maintain an explicit allow-list, e.g. `.mp4/.m4v/.mov`), then
  move any non-current-clip video/screenshot into `trash/`.
- `pd site [--category=X]` — `site.py`: resync `thumbnails/` from `screenshots/` (Pillow resize,
  delete orphans), regenerate the HTML page(s) for the given category (or all distinct categories
  present when omitted) plus `content/index.html` linking to each category page.
- `pd report` — `report.py`: compute all DESIGN.md stats via `db.py` queries + filesystem scans,
  print to stdout, and also write the same text to `report/<timestamp>.txt`.

## Implementation order

Build and check in incrementally rather than as one giant change:
1. **Foundations** — `pyproject.toml` deps + `pd = "pd:main"` entry point (typer app), `paths.py`,
   `db.py` + schema, `ids.py`, `scene_id.py` fix, `pd init`. Verify: `pd init` in a scratch dir
   produces the exact directory tree + valid schema.
2. **mpv controller** — `mpv.py` in isolation, exercised via a small script against a real local mpv.
3. **Create tab + capture workflow** — Create screen, `capture.py`, filename builders.
4. **List tab**.
5. **Scene view modal** (main pane + 3 list panes + all sub-modals).
6. **`pd sync`**.
7. **`pd site`**.
8. **`pd report`**.

## Testing

- `pytest` unit tests for the non-UI logic: `ids.py`/`scene_id.py` (format + collision regeneration),
  `hash.py` (already testable), `db.py` (schema + CRUD round-trips via `tmp_path` sqlite files),
  `sync.py`/`report.py`/`site.py` computation logic (overlap detection, current-clip selection,
  duration buckets) against fixture DB rows and fake files — no real mpv/ffmpeg required for these.
- `mpv.py`'s JSON framing/command layer gets unit tests against a mock Unix socket; actual mpv spawn
  is verified manually (real mpv binary required).
- TUI screens: manual verification per phase (start the app, exercise the golden-path keybindings)
  since they depend on a live mpv instance and real video files — call this out explicitly rather than
  claiming automated coverage of the UI layer.

## Verification

- After each phase, run `uv run pytest` and manually exercise the new command/screen against a scratch
  project directory with a short real test video, confirming DB rows, generated files, and on-screen
  behavior match DESIGN.md before moving to the next phase.
